### Dynamic batching이란?
동적배칭(Dynamic batching)은 작은 Mesh들의 정점 데이터를 CPU에서 변환하고 결합해 렌더링 하는 방식이다.

정적배칭과 다르게 움직이는 오브젝트에도 적용 할 수 있다.

### 내부 동작 원리
예를 들어 작은 큐브 3개가 매 프레임마다 움직이고 있다고 가정하였을 때, 정적 배칭과 같이 사전에 월드 좌표로 변환하여 고정해 둘 수는 없다.

따라서 동적 배칭은 렌더링 과정에서 CPU가 각 Mesh의 정점 데이터를 처리한다.

**동적 배칭의 내부 동작 과정은 다음과 같다.**

1. 동일한 Material을 공유하는 등 배칭 조건을 만족하는 Mesh를 확인한다.
2. CPU가 각 Mesh의 정점을 월드좌표로 반환한다.
3. 변환된 정점 데이터를 하나의 버퍼에 결합한다.
4. 결합된 데이터를 하나의 Draw Call로 렌더링한다.
5. 매 프레임 필요한 정점 변환 및 결합 작업을 다시 수행한다.

이러한 방식으로 여러 오브젝트를 각각 렌더링하는 대신 하나의 [[Draw Call]]로 처리하여 CPU의 렌더링 명령 제출 비용을 줄일 수 있다.

다만 CPU에서 정점 변환 및 결합 작업을 수행해야 하므로, 절약되는 Draw Call 비용보다 추가되는 CPU 연산 비용이 크다면 오히려 성능이 저하될 수 있다.

### 동적배칭은 오히려 느려질 수 있다?
일반적인 Mesh 렌더링에서는 정점 변환 연산을 GPU의 [[Vertex Shader]]가 수행한다.
하지만 동적배칭은 여러 Mesh를 합치기 위해 **CPU가 일부 정점 변환 작업을 직접 수행**하게 된다.

따라서, 일반 렌더링에서 기존 Draw Call 준비, 제출 비용이 발생할 때
동적배칭은 감소된 Draw Call 비용 + 정점 변환 처리비용이 추가적으로 발생하게 되는데
이러한 구조속에서 절약한 Draw Call 비용보다 **정점 전환 비용이 더 크다면 최적화 효과가 없거나,** 
**오히려 성능이 약화**될 수 있다.

이러한 이유로 인해 [Unity 2022~2023계열 공식문서](https://docs.unity3d.com/kr/2023.2/Manual/dynamic-batching.html)에서는 일반 Mesh 동적배칭의 제한을 설명한다.

결과적으로 **동적배칭을 무조건 사용하기보단 대상 플랫폼에서 CPU렌더링 시간이 실제로 감소하는지 확인하는 것 이 중요하다.**


### 장점과 단점

| 장점                          | 단점                         |
| --------------------------- | -------------------------- |
| Draw Call 감소로 CPU 렌더링 비용 절감 | CPU의 정점변환 및 결합 비용 발생       |
| 움직이는 오브젝트에도 적용가능            | 작은 Mesh에만 적용 가능            |
| 배칭조건 충족 시 자동 처리             | Material 및 정점 속성등 배칭 조건 제한 |
| 개별 Randerer컬링 가능            | CPU 처리 비용으로 성능 저하 가능       |
