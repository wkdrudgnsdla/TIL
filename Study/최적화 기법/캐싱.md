### Caching(캐싱)이란?
캐싱은 자주 사용하거나 반복적으로 계산해야하는 데이터를 미리 저장해두고, 이후 동일한 데이터가 필요할 때 저장된 값을 재사용하는 최적화 기법이다.

반복적인 데이터 탐색, 계산, 로드등의 작업을 줄여 CPU 연산비용이나 데이터 접근 시간을 감소시키는 것을 목표로 한다.



### 캐싱의 주요 개념

| 개념                 | 설명                               |
| ------------------ | -------------------------------- |
| Cache              | 재사용할 데이터를 저장하는 공간 또는 구조          |
| Cache Hit          | 요청한 데이터가 캐시에 존재하는 경우             |
| Cache Miss         | 요청한 데이터가 캐시에 존재하지 않는 경우          |
| Cache Invalidation | 기존 캐시 데이터가 유효하지 않아 갱신하거나 제거하는 과정 |
| Cache Lifetime     | 캐시된 데이터를 유지하는 기간                 |



### 내부 동작원리
1. 필요한 데이터에 접근하거나 계산 결과를 요청한다.
2. 해당 데이터가 캐시에 존재하며 유효한지 확인한다.
3. 캐시가 없거나 유효하지 않다면 원본 데이터에 접근하거나 계산한 뒤 결과를 저장한다.
4. 유효한 데이터가 존재하면 기존에 저장한 데이터를 사용한다.
5. 원본 데이터가 변경되거나 더이상 필요하지 않다면 캐시를 갱신하거나 제거한다.

### 장점과 단점

| 장점                      | 단점                      |
| ----------------------- | ----------------------- |
| 반복적인 데이터 탐색 및 계산비용 감소   | 캐시 데이터 저장을 위한 메모리 사용    |
| 데이터 사용으로 접근시간 단축 가능     | 원본 데이터 변경 시 캐시 갱신 필요    |
| 불필요한 API 호출 및 연산 감소     | 오래된 데이터를 사용할 위협 존재      |
| 반복 작업이 많은 환경에서 성능 개선 가능 | 캐시 관리 로직으로 코드 복잡도 증가 가능 |



### Unity에서의 활용
- 컴포넌트 캐싱: `GetComponent<T>()`로 얻은 컴포넌트 참조 재사용
- Shader Property ID 캐싱: `Shader.PropertyToID()` 결과 재사용
- Transform 캐싱: 자주 접근하는 오브젝트의 Transform 참조 저장
- 계산 결과 캐싱: 반복적인 수학 연산 및 스탯 계산 결과 재사용
- Animator 파라미터 캐싱: `Animator.StringToHash()` 결과 재사용
- 데이터 캐싱: 반복적으로 조회하는 게임 데이터 저장 및 재사용
- 컬렉션 캐싱: 반복적으로 사용하는 배열, 리스트 등의 참조 및 데이터 재사용
