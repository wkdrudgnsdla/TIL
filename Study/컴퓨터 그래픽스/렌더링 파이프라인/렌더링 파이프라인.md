### Rendering Pipeline(렌더링 파이프라인)이란?
렌더링 파이프라인은 3D 또는 2D 씬의 데이터를 처리하여 최종적으로 화면에 이미지를 출력하기까지의 일련의 렌더링 과정을 의미한다.

Unity에서는 CPU가 카메라와 오브젝트의 렌더링 정보를 준비하고, GPU가 전달받은 데이터를 처리하여 최종 이미지를 생성한다.

이러한 과정에는 정점변환, [[Clipping]], 레스터화, 셰이더 실행, 깊이테스트 등이 포함된다.

###### 렌더링 파이프라인의 주요 요소

| 구성요소                        | 역할                |
| --------------------------- | ----------------- |
| CPU                         | 렌더링 대상 선정 및 명령 준비 |
| Graphics API                | 렌더링 명령을 GPU에 제출   |
| [[Vertex Shader]]           | 정점의 좌표변환 및 속성 처리  |
| Clipping                    | 가시영역 밖의 도형 절단     |
| Rasterization               | 도형을 프레그먼트로 변환     |
| Fragment Shader             | 프레그먼트 색상등 계산      |
| Depth test                  | 깊이값을 비교하여 가시성 판단  |
| Framebuffer / Render Target | 렌더링 결과 저장         |
중요한점은 렌더링 파이프라인이 GPU 내부 처리 과정만을 의미하는것이 아닌,
Unity 관점에서는 CPU가 렌더링을 준비하고 명령을 구성하는 과정까지 묶어서 이해하는게 좋다는것이다.

Unity에서의 일반적인 렌더링 과정을 CPU와 GPU로 구분하면 위와 같다.

###### 구체적인 설명
1. 렌더링 대상 확인
   CPU는 현재 카메라를 기준으로 렌더링할 오브젝트를 결정한다.
   대표적으로 [[Frustum Culling]]을 사용하여 카메라 가시영역 밖의 오브젝트를 제외하고, 설정에 따라
   [[Occlusion Culling]]을 사용해 다른 오브젝트에 가려진 대상을 제외할 수 있다.
   
2. 렌더링 명령 준비
   렌더링할 오브젝트가 준비되면 Mesh, Material, Shader, Rander Queue등의 정보를 기반으로 명령을 준비한다.
   이 과정에서 [[Batching]], 오브젝트 정렬, 렌더링 상태 설정등을 수행하며, 그래픽 API를 통해 GPU에 
   [[Draw Call]]을 제출한다.
   
3. 정점 데이터 처리
   GPU는 [[Vertex Buffer]]와 [[Index Buffer]]등을 이용하여 필요한 정점데이터를 읽는다.
   Vertex Shader는 정점의 좌표를 변환하거나 UV, Nomal등의 정점 속성을 처리한다.
   대표적으로 로컬좌표를 [[Clip Space]]로 변환하는 과정을 수행한다.
   
4. 도형 구성 및 Clipping
   처리된 정점을 기반으로 삼각형등의 기본 도형을 구성한다.
   이후 Clipping을 통해 카메라의 가시영역에서 벗어나는 도형을 잘라낸다.
   
5. Rasterization
   Clipping을 거친 도형에 [[원근 나눗셈]]과 뷰포트 변환을 적용하고, 화면에서 어떤위치를 차지하는지 계산한다.
   이후, 삼각형등의 도형을 프래그먼트로 변환한다.
   
6. Fragment Shader
   각 프래그먼트에 대해 Shader를 실행하여 색상등 출력값을 계산한다.
   텍스쳐 셈플링, 노멀 매핑, 조명 계산등의 작업을 수행할 수 있다.
   
7. 깊이테스트 및 결과 저장
   깊이테스트를 통해 현재 프레그먼트가 깊이 조건을 만족하는지 판단한다.
   필요한 Stencil Test, Blending 등의 작업을 수행한 뒤 Render Target에 결과를 기록한다.
   
8. 렌더링 결과에 필요한 경우 포스트 프로세싱, UI 합성 등의 추가 작업을 수행한다.
   최종적으로 완성된 이미지가 화면에 표시된다.




### 특징과 제약

| 특징                    | 제약                         |
| --------------------- | -------------------------- |
| 렌더링 과정을 단계별로 구성       | 각 단계에서 CPU 또는 GPU 처리비용 발생  |
| GPU 병렬처리를 활용 가능       | GPU 연산량과 메모리 대역폭에 따른 성능 제한 |
| 셰이더를 통해 렌더링 결과 제어 가능  | 복잡한 셰이더는 처리비용 증가           |
| 배칭, 컬링등의 최적화 기법 적용 가능 | 최적화 결과는 렌더링 환경에 따라 달라짐     |
| 다양한 렌더링 패스와 시각효과 지원   | 추가 패스로 드로우콜 및 GPU 연산량 증가   |
