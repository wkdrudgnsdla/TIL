## 추상클래스
추상클래스란 일반 클래스와 [[Interface]]의 중간정도이다.

###### 인터페이스와 닮은 면
- 모든 자식이 반드시 오버라이딩 해야하는 메서드 껍데기들을 포함하고있다.
- 컴포넌트로써 오브젝트에 붙일 수 없다.
###### 일반 클래스와 닮은 면
- 메서드의 껍데기만 명시할 수 있는 인터페이스와는 다르게 메서드의 일부 실제 구현을 포함할 수 있다.


##### 추상클래스 만드는법
`abstract` 키워드를 앞에 붙이면 해당 클래스가 추상클래스가 된다.


## 키워드로서의 추상
##### 그럼 virtual과 abstract는 뭐가 다름?
`virtual`은 자식 클래스가 이 함수를 오버라이딩 하게 허용할 뿐 굳이 안해도 된다.
오버라이딩 하지 않는다면 부모가 정의한 내용대로 자식 클래스에서 동작하게 된다.

하지만 `abstract`는 부모가 직접 내용을 정의하는게 불가능하기에 반드시 자식에서 오버라이딩 하는것을 강제한다.

쉽게 설명하자면 `Monster`이라는 부모 클래스에서 `Move()`라는 버츄얼 메서드가 있고,
`Attack()`이라는 추상메서드가 있다면, `Move()` 메서드는 부모 클래스에서 정의한 내용대로
`Monster`을 상속한 `Skeleton`과 `Goblin` 클래스에서 오버라이딩 하지 않아도 동작하지만

`Attack()`메서드는 무조건 `Skeleton`과 `Goblin`에서 오버라이딩해서 내부 내용을 지정해야 동작하게된다.

```csharp
public abstract class Monster : Monobehaviour 
// abstract 메서드가 있는 클래스는 무조건 abstract여야 함
{
	public virtual void Move()
	{
		Debug.Log("이동");
	}
	
	public abstract void Attack();
}
```
위와 같은 Monster 부모클래스가 있다 가정하였을 때,
```csharp
public class Skeleton : Monster
{
	// Move()는 override하지 않아도 실행하면 부모의 "이동"이 출력됨 
	
	public override void Attack() // Attack()은 override하지 않으면 에러가 발생
	{ 
		Debug.Log("칼 공격"); 
	}
}
```
과 같은 형식으로 상속한 스켈레톤 클래스에선
virtual 메서드인 `Move()`는 오버라이딩하지 않아도 부모클래스에서 정의한대로 동작하지만,
`Attack()`은 무조건 오버라이딩 해주어야한다.


### 정리
**`abstract`는 해당 클래스나 메서드가 완성된 형태로 직접 사용되기보다는, 상속을 통해 구현하여 사용하도록 명시하는 키워드이다.**
- **추상 클래스**: 직접 인스턴스를 생성할 수 없으며, 상속을 위한 부모 클래스로 사용한다.
- **추상 메서드**: 부모에서 내부 구현을 하지 않고, 이를 상속받은 **구체 클래스에서 반드시 `override`하여 구현해야 한다.**
